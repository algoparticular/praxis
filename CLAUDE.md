# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Anima** is the first interactive proposal from *Algo Particular* — a bilingual (Spanish/English) Progressive Web App offering a digital Oracle card deck for self-discovery and reflection. The oracle deck contains 33 cards, written by Belén Brito. Hosted on Cloudflare Workers as static files (`wrangler.jsonc`, headers in `public/_headers`): every push to `main` is built (`npm run build`) and deployed by Workers Builds; the domain, its DNS and the move from Netlify are in `docs/cloudflare.md`. Netlify served it until November 2026 (`netlify.toml` stays until its site is deleted).

## Commands

```bash
npm run dev      # Start local dev server (Vite)
npm run build    # Production build → dist/
npm run preview  # Preview production build locally
npm run check    # Everything a pull request must pass (below), in order
```

**Checks** (run on every pull request by `.github/workflows/checks.yml`, and locally with `npm run check`):
- `npm run lint`: ESLint (`eslint.config.js`). Errors block (undefined names, broken Vue templates); unused variables in old code are only warnings.
- `npm run check:cards`: `scripts/check-cards.mjs`. Every card in `src/data/cards.json` is complete (texts in both languages, colours, pictures and thumbnail on disk), `cardScenes.js` only lists real cards, and after a build every card has its share page and picture in `dist/`.
- `npm run check:docs`: `scripts/check-docs.mjs`. The card table in `docs/cartas.md` (name, verb, chord, scene) is generated from the card data; this fails when it is out of date. Fix it with `npm run docs`. When a card's verb becomes playable, add its id to `PLAYABLE` in that script.
- `npm run check:budget`: `scripts/check-budget.mjs`. Size budgets for the build (gzipped JS per chunk, pictures per file and per group). When something legitimately grows, raise its line in that file in the same pull request.
- `npm run check:smoke`: `scripts/smoke.mjs`. Serves the build and opens every page and card (cards with a scene also on a phone-sized screen) in Chromium; fails on JavaScript errors, console errors, 404s on our own files or a page that did not draw. Needs `npx playwright install chromium` once.

These cannot see what a real GPU or a real phone does (flicker, disappearing layers), so scenes are still tried by hand on a phone before merging. Adding `?fps` to any address (e.g. `/card/31?fps`) shows a frame counter (`FpsMeter.vue`, mounted in `App.vue`, measuring with the same `useFramePace.js` as the analytics): frames per second, slow frames (over 25 ms), stutters (over 50 ms), the worst frame and the time measured; it stays on for the tab (`sessionStorage`), starts again on every page or when touched, and `?fps=0` turns it off.

## Architecture

**Stack:** Vue 3 (Composition API, `<script setup>`) + Vue Router 4 + Vue i18n 9 + Vite 5. No TypeScript, no centralized state store (Vuex/Pinia).

**Routing** (`src/router/index.js`): SPA: any address that is not a file gets `index.html` (`not_found_handling` in `wrangler.jsonc`), and pages are served without a trailing slash (`/card/3`, `html_handling`). Key routes:
- `/` → Landing page
- `/praxis` → Home hub (choose Full Deck or The Nine)
- `/oracle` → Full 33-card deck view
- `/oracleTheNine` → "The Nine" (9-card subset reading)
- `/card/:id` → Individual card detail (`?jugar` gives it its game, see Card pages)
- `/share/:id` → Social sharing page
- `/sid` → Sid's world (the puppet lab; `/lab/sid` redirects here)

**Data layer:** the cards are static data, no database. `src/data/cards.json` is the source of truth (texts in both languages, colours, picture) and `public/cards/` holds the illustrations (`N.webp`, 2160 px), a 1440 px version of each (`1440/N.webp`) and thumbnails (`thumb/N.webp`), the last two made by `npm run thumbs`; `src/data/cards.js` exposes `deck`, `getCard(id)` and `pictureUrl(card)`, which picks the 1440 one unless the stage needs more real pixels (large high-density screens): every place that shows the full illustration (the oracle's flip, the card that grows into the stage, `SceneFlat`, Share) goes through it so they all load the same file. Airtable is no longer used. Each card also has a `verb` (one of the seven in `src/data/verbs.js`, see `docs/verbos-y-dinamicas.md`): the dynamic of its future game. How to edit a card: `docs/editar-cartas.md`.

**Internationalization:** `vue-i18n` with `src/json/en.json` and `src/json/es.json`. Default language is Spanish or whatever is stored in `localStorage`. Language switching is handled in the `Menu` component.

**Component patterns:**
- Views (`src/views/`) are page-level components mounted by the router.
- Reusable UI lives in `src/components/`. Template components (e.g., `CardTemplate`, `OracleTemplate`, `DeckTemplate`) handle display logic; skeleton variants (e.g., `CardTemplateSkeleton`) serve as loading fallbacks used with Vue `<Suspense>`.
- Animations use `vue-kinesis` (parallax effects) and CSS transitions for route changes (fade).

**Card pages (immersive scenes):** `/card/:id` is a full-screen *stage* (`CardTemplate.vue`) with the card's name over it, and the reading (description, affirmation, invitation) below. What fills the stage is a *scene*, chosen per card in `src/data/cardScenes.js` (`sceneFor(id)`):
- **With or without its game:** a card opened from the oracle (`/oracle`, `/oracleTheNine`) or by its address is alive (its parts answer a touch and sound, as in its game) but has no game: no ghost hand, no rulito, no `rulito` sound (`cardGame` in `src/composables/useCardGame.js`, read by `useGhostHand.js`, `Rulito.vue` and `play` in `useSound.js`). It has its game when opened from Sid's world (`play` on `CardTemplate`), from "Las cartas" (`/deck`, `handOffCard` adds `?jugar`) or with `?jugar` in its address (the GDD's links). Decided on 23 November 2026: the games are released a few at a time, in the world. `card_viewed` and `card_left` carry `game`, and only a card with its game reports `scene_milestone` (so milestones still mean a game played). What a scene does when all its parts are done without a game (its finale still sounds, with no rulito) is still to be tried on a phone.
- **WebGL stage:** every scene is drawn whole in WebGL by `useLayerStage.js` (one canvas: layers as planes at depth, camera parallax from the pointer or the tilt; shader effects per layer: wind, shimmer, water, sheen, sink, blur, vignette, clip, and a mask to one side of a `field()` (`maskBy`, also for particle groups: Ciclos's moon and sun); discs, glows and fields (two liquids that never mix, with bubbles of one in the other; with `alone` only the second, over what is behind: Armonía's currents; `uDent` presses a dent into the edge, which its masks follow: Ciclos's day flowing over the moon) drawn in code; a layer's `clip` can fade at its top and bottom (`soft`: Compromiso's lit path); `useStardust` groups drawn among the layers with `{ stage }`; bloom only while `stage.bloom` > 0, the rulito moments). Touch targets stay DOM elements moved over what they belong to (`boxOnScreen`, `toScreen`). Vipassana draws its field of cells with `useVipassanaField.js` through `stage.underlay()`; the landing hero keeps `useCellField.js` as it was. The scenes listed with `stage()` in `cardScenes.js` fall back to `SceneFlat` without WebGL. On iOS the tilt is asked for on the first touch of a visit when it is not coming already, unless the person said no (`useTilt.js`). Details: `docs/escenas.md`.

- **The ghost hand** (`useGhostHand.js`) is every game's hint, with no words: left alone 7 s (`HINT_AFTER`, and again 7 s after a win), a fingertip of light made of dots does the verb's gesture on the real place (`gesture.tap`, `taps`, `hold`, `rub`, `sling`, `drag`, `slide`), twice, and goes at once on any touch; never with reduced motion. The rulito is born where the original card draws it, or over a character (never at a fixed place on the screen). Details: `docs/escenas.md`.
- **three.js** is always imported on demand from `src/three.js`, which re-exports only the classes the app uses (so the build does not carry the whole library); using another class means adding it there.
- **Skies are never pictures:** a flat or gradient sky (and a plain disc of a sun or a moon) is drawn in code from the card's colours (a CSS gradient worked out by the converter, `disc()`, `glow()`), not shipped as a full-screen image; only what has drawing in it is a picture.
- **Particles and stars are never pictures:** wherever an asset is a field of dots, stars or dust, the scene draws it as real particles instead, with `useStardust.js` (three.js `Points`, one canvas can hold several groups, each one draw call, with `shift(i, x, y)` to follow a layer's parallax and `dynamic` groups that move every frame; `look: 'hard'` for the flat dots of the night skies, `'soft'` for glowing dust or embers; `startStardust` is the safe way to start one from a component). The shooting stars of the 2D night skies (`useStarField.js`: the landing's oracle block, `/deck` and the tables of `/oracle` and `/oracleTheNine`) are like Dana's, in the colours of their sky: a soft cream head and one yellow stroke that narrows and fades; most pass far and are silent, about one in five passes near, bigger, and only that one sounds (`onShoot`). The oracle block's sky also draws constellations with its own stars (`constellation()` in `useStarField.js`; the points come from the mode's SVG icon through `iconConstellation.js`): looking at a way in (hover or focus on `ModeSelector.vue`, which emits `show`) the nearest stars travel one after the other to the icon's shape, made bigger about it and always centred on it (smaller on a phone, so it stays whole), and threads of dots in the mode's colour join them; on a phone it forms while a finger holds the mode, and once it is whole (`CONSTELLATION_TIME`, 2 s, by the clock so a slow phone takes no longer; it shines and `star` sounds) letting go goes in; let go before, the stars go home and nothing happens, and a quick tap still goes straight in (only a real mouse hovers and only the keyboard focuses, so the mouse events a phone makes up after a long press cannot draw it again).
- `src/data/sceneNames.js` names the cards with a scene, for analytics (`sceneNameFor`, re-exported by `cardScenes.js`) and the card table of `docs/cartas.md`; `check:cards` fails if the two lists differ.
- Every other card uses `SceneFlat` (its square illustration, feathered into the card colour, drifting slowly), alive in code until it gets its own scene: a glow of its `colorAlt` breathing behind the picture, and motes of light in the colours of the card's chord (each note a chakra, `chordColors()` in `src/data/chordColors.js`: crisp dots and a few soft halos, rising, moved by the finger, following the tilt); a tap strums the chord (`star`) and the motes flare.

**Colours:** the brand is the cream (`#F7F8F1`, and `#E9EDD8` for highlighted surfaces), the navy (`#143246`) and the coral (`#FF6F61`), always the accent: the orange of the logo is not a brand colour any more, it belongs to Samas only. Each chakra (and so each character) has a colour in `src/data/chakraColors.js`: six share the coral's lightness and saturation and the root is a deeper carmine, so it is not taken for the coral, each with a `light` version (fills, illustration, the navy) and an `ink` one (text on the cream). The oracle's cards light up with those seven; the same values are the character variables in `style.scss`.

**Sound:** made with Web Audio (`src/audio/synth.js`, behind the switch in `useSound.js`, which is the speaker icon beside the menu button in `Header.vue`, not inside the menu): a pad, chimes and drops as ambience, and short effects (`tap`, `star`, `pick`, `flip`, `shuffle`, and the ones of the scenes with a game, like `flow` for the current of Fluir, `sing` for Sacca's lookout or `heartbeat` for Sid's heart in Sila). Everything is synthesised except the bowls (every chime and bell note of every effect but the water's `ripple`, which keeps the synthesised one): they ring on a vibraphone played with soft mallets, six recorded notes one a fifth apart (`public/assets/sound/vibraphone/<midi>.mp3`, 288 KB, MP3 64 kbps, made by `scripts/make-vibraphone.mjs` from the Versilian Community Sample Library, CC0) retuned to each note, fetched only when the sound is turned on (`loadVibraphone`, called by `enable` in `useSound.js`) and kept offline like the pictures (the `sounds` cache in `vite.config.js`); until they arrive, and for notes more than a fourth beyond them, the synthesised bowl (`synthBell`) plays. When a game's rulito appears it sounds `rulito`: the card's chord climbing to the octave above and ringing there (Gurdjieff's law of octaves: what is completed starts again on the next do). A card whose chord is a dominant seventh resolves first (`resolve`, to the chord a fifth below): in Encender (Evolución) B7 goes to E major, Kätus's note, Creatividad's tune C7 to F major, the heart, and Sacca's echo and Sila's heartbeat G7 to C major, the root. Two channels can be set apart in the menu (`Menu.vue`, two sliders shown only with `hasAudio`, which the menu in `Header.vue` passes and the footer, the same `Menu` component, does not; music at half by default, in `useSound.js`: `musicVolume` for the pad, chimes and drops, `effectsVolume` for the touch sounds; each is a gain bus into the master, squared so the lower half of a slider is really quieter, remembered in `localStorage`). The master (`createMaster` in `synth.js`) softens the band around 2.8 kHz, where the ear and a phone's speaker are most sensitive (the high bowls sounded harsh on an iPhone), and its compressor is only a gentle limiter, not the browser's default. Turning the sound off stops every ambience started (`ambients` in `useSound.js`), fades each with `setTargetAtTime` and cuts it from the graph after the fade, so no instance can be left playing. The app sounds in G major (Aura, Particular and Samas; it shares a note with the chord of 27 of the 33 cards); each card has its own chord in `src/data/cardChords.js` (each note is a chakra and a character of Algo Particular: Do root/Sporá, Re sacral/Samas, Mi plexus/Kätus, Fa heart/Vulpes, Sol throat/Aura, La third eye/Huit, Si crown/Particular; major opens, minor turns inwards, a dominant seventh is a tension that resolves to the chord a fifth below, a major seventh opens calmly, a minor seventh turns inwards with a door left open (only the dominant is a tension: the stable sevenths resonate like any other chord); the card's text chooses the chord, not the characters drawn on it, and cards that resonate may share one; the reason for each card is in `docs/cartas.md`). On a card page (`App.vue` watches the route) the pad and chimes move to that chord and the scenes' `tap` and `star` play in it: taps walk the chord as a small melody, stars strum its notes. Stars in quick succession get quieter and shorter so a burst does not tire the ear. The card that is silence (Tu verdad, 10; `isSilent` in `cardChords.js`) quiets the music: App.vue calls `setHush` (`useSound.js`), and the ambience's own hush gain (`hush()` in `createAmbient`, after its fade, so start, stop and the switch are untouched) fades the pad, chimes and drops out over a few seconds and brings them back when the card is left; only its heartbeat is heard, very soft (`heart`: `heartbeat` always on Fa, on the effects bus).

**Sharing:** a card is shared from the "share this card" button at the end of the reading, after the invitation (`share_opened`, `from: 'reading'`). There is no button over the scene any more: it sat over the drawing.

**Share previews (og:image):** crawlers don't run JS, so `scripts/cardMetaPlugin.js` (Vite plugin, runs after `vite build`) writes `dist/card/<id>/index.html` with each card's own og:/twitter: tags (Spanish name and affirmation) and `dist/og/<id>.jpg` (1200x630, illustration over the card colour). Cloudflare serves those static files before falling back to the app. Cards with no image are skipped and fall back to the generic tags in `index.html`. It also writes a page for each other address worth finding (`PAGES`: `/sid`, with its own picture, `/deck`, `/oracle`, `/oracleTheNine`), each with its own title and words in Spanish (taken from the app's own texts and the GDD), and `dist/sitemap.xml` with all of them (`public/robots.txt` points to it); every page, the landing's `index.html` too, has its `canonical` and `og:locale`, and a card's `og:image:alt` names it. The landing's own title and words are in `index.html`. In the app the tab's title follows the page and the language (`pageTitle` in `main.js`). The pictures that are not a card's are in `public/share/` (1200x630): `home.jpg`, the generic one in `index.html` (Sid on his rug over the oracle block's navy sky, its stars drawn in code: `scripts/make-share-images.mjs`), and `sid.jpg`, a moment of the world itself (`scripts/shot-sid-share.mjs`, with the dev server running: Sid alone in the middle, in lotus in Ciclos, a few steps away from the tree, as its red sun comes up, with the camera looking up as when a constellation forms but by day, closer than in the app; through `window.__sid` it sets the world's clock and holds the look, and a seeded `Math.random`, its seeds tried until the zone is Ciclos, picks the world). Every page has a `description` too (the card's affirmation on a card's).

**Analytics:** anonymous usage analytics with PostHog, cookie-less and in memory (`src/analytics.js`, off unless `VITE_POSTHOG_KEY` is set; events, funnels and privacy guarantees in `docs/analitica.md`). Card pages tell one story per visit (`startCardVisit`: time, touches on the scene, whether the reading was reached) and scenes with a game report milestones with `sceneMilestone`. `card_left` and `table_left` (the 3D tables of `/oracle`, `/oracleTheNine` and `/deck`, from `startTableVisit` in `CardTable.vue` and `DeckRing.vue`) also carry how smoothly the page was drawn (`useFramePace.js`: average fps, % of slow frames, stutters, worst frame, plus cores and pixel ratio as a hint of the device); nothing is measured when nothing would be sent. Sid's world tells its own story the same way (`startWorldVisit`, called by `LabSid.vue`: `world_entered`, a few moments inside, such as the first step, each zone reached, each place meditated and each card opened from it, and `world_left` with the totals and the frames); of what the world keeps on the phone (`worldMemory.js`) only counts are sent: which visit it is, how many fragments of the story and how many kinds of plant (`world_entered`, `world_fragment`, `world_notebook_opened`, `world_plant_discovered`), and the first visit's lesson (`world_first_seed`).

**No accounts:** there is no sign-in. A first Firebase sign-in (`/sign-in`, `/register`) was never finished and was removed; those addresses go to the landing. Accounts, if they come, start from what they are for (for example keeping the card of the day or a person's rulito).

**PWA:** the service worker is built by `vite-plugin-pwa` (Workbox, configured in `vite.config.js`) as `dist/serviceWorker.js` and registered in `App.vue`. The app, the fonts and the deck's thumbnails are saved on the first visit; pictures (illustrations, scene layers) as they are seen. With internet, the page and the pictures are always asked for first (`NetworkFirst`; an unchanged picture costs a 304, Cloudflare revalidates `/assets` with its ETag), so a deploy is seen at once and an old app is never mixed with new pictures or a new scene with old ones (a picture that changes keeps its name); offline, or when the network does not answer in 3 s (pages) or 4 s (pictures), what was saved is used, and an address never visited opens the app's own `index.html`. A deploy takes over at once, and an app left open is asked again whenever it comes back to the front (`src/pwa.js`, at most every 10 min): if a new version took over it reloads at once when nothing was touched yet, otherwise on the next return; `main.js` reloads once if an old page asks for a chunk that is gone (`vite:preloadError`). `public/manifest.webmanifest` configures standalone install behavior: its `id`, `description` and `lang`, the icons (`icon-192.png`, `icon-512.png`, the latter also `maskable`: the mark is well inside the safe zone), the cream of the icon as the splash's background and the navy as `theme_color`, three shortcuts (the oracle, Sid's world, the cards) and the screenshots the install dialog shows (`public/screenshots/`, made by `scripts/shot-manifest.mjs` from a build served). The browser's bar takes the colour at the top of the screen on every page and as it scrolls (`src/composables/topColour.js`, started in `main.js`): it is read from the page itself (`colourAt`: the background colours and vertical gradients of what is at the top, through `elementsFromPoint`; a scene whose top is drawn in WebGL says what is there with `el.topColourAt(y)` on its root, as Compromiso's dome and cap, Celebración's roof of leaves on a phone and Upekkha's sky, the half that covers more of the width as its edge moves, or `--top-colour`), on scroll, on every page change and resize and every 400 ms, and goes to `<meta name="theme-color">` (Chrome on Android, Safari up to iOS 18), `<body>`'s background (Safari 26 ignores theme-color and blends the transparent fixed header over the body's colour) and `--strip` (the strip under the clock in the installed app). If the phone closes the installed app in the background, it starts again at its `start_url` (the landing): whoever was in Sid's world in the last 6 h goes back into it (`src/composables/worldResume.js`, written by `LabSid.vue` while the world is open and cleared on walking out of it in the app, read by the router on the first page; only in `display-mode: standalone`; Sid starts again where every visit starts). Opened from the iPhone's Home Screen the page goes under the clock (`black-translucent`, `viewport-fit=cover` in `index.html`, read by iOS when the icon is added): Sid's world shows its sky there (laid out on the screen below the strip, as it was when the page started below it, so the strip is more sky over it: `view.top`, read from `env(safe-area-inset-top)`, in `LabSid.vue`), every other page a strip as tall as the clock (`.status-strip` in `App.vue`, only in `display-mode: standalone`) and starts below it; the strip takes the colour at the top of the page (`--strip`, from `topColour.js`, navy until it is known); the header sits at `env(safe-area-inset-top)`. In Sid's world the canvas draws the sky, so `.lab` takes the sky's colour at the top edge (`topColour()` in `sidWorld.js`) and `topColour.js` reads it from there.

**Fonts:** Nunito (text) and Caveat (titles, handwriting), both served from `src/assets` (no Google Fonts or other font hosts). `<html lang>` follows the chosen language (`main.js`).
